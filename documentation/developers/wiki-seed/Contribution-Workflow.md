# Contribution Workflow

## Branching

- Use focused feature branches for non-trivial changes
- Keep main in a healthy and releasable state

## Commits

- Use clear commit messages that describe impact
- Keep unrelated changes out of the same commit

## Pull Requests

- Explain what changed and why
- Include verification steps
- Link related issues or discussions
- Update docs when behavior changes

## Review Focus

- Correctness and regression risk first
- Then maintainability and architecture fit
